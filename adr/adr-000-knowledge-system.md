# ADR-000: Repo Knowledge System

Status: proposed
Date: 2026-09-25
Owner: Clark Koenigs
Applies to: every repo scaffolded or migrated by `ds`

This is the standards repo's first entry and it describes the system it
lives in. It is itself a Standard with the ID `adr-000`, so every repo's
manifest will record whether it adopted this ADR.

## Context

`ds new` copies the same doc content into every repo. Two hundred repos
later, each copy has drifted from the others and from the code. Standards
change in one place and reach nowhere. Agents (and people) opening a repo
cannot tell which sentences are org policy, which are local fact, and which
are stale.

The root cause is copying. Content that exists in 200 places has 200
chances to drift. The fix is to make sure every fact exists exactly once and
everything else points at it.

## Decision

Every line in a repo's docs is one of three kinds. Only one kind is written
by hand inside the repo.

| Kind | Source of truth | Lives in the repo as | Changes by |
|------|-----------------|----------------------|------------|
| Inherited | `standards/` repo | a pointer, never text | editing the standard once |
| Local | the interview, then the team | text, provenance-tagged | humans or agents editing this repo |
| Derived | the code (graph, API surface) | generated text, never hand-edited | regeneration |

Five primitives implement this. One verb, `reconcile`, keeps them
consistent.

### 1. Standard

A versioned document in the `standards` repo with a stable ID.

```
standards/
  adr/adr-000-knowledge-system.md
  adr/adr-014-uv-not-pixi.md
  glossary.md            # id: glossary
  layout.md              # id: layout
  naming.md              # id: naming
  index.json             # generated: {id, version, hash, title, supersedes, applies_to}
```

Rules:
- IDs never change. Versions increment. `index.json` is regenerated by CI on
  every merge and is the only thing repos read.
- An ADR has `applies_to` (glob over repo tags, default `*`) so a dbt-only
  decision is not pending on every Python package.
- An ADR may `supersede` another; adopting the new one resolves the old.

### 2. Pointer

`[[id]]` or `[[id@version]]` inside any doc. A pointer is resolved on read
by `ds` (for humans: `ds docs` renders; for agents: the `read_standard`
tool returns the text). The repo never holds the standard's prose.

```markdown
## Conventions
This repo follows [[layout]] and [[naming]]. Domain terms are in
[[glossary]]. Dependency management: [[adr-014]].
```

A pointer to a retired or unknown ID fails the local hook. A pointer with no
version means "current"; a pinned version is a deliberate choice recorded in
the manifest.

### 3. Manifest

`.ds/manifest.toml`. The negotiation record. One entry per standard the
index says applies to this repo.

```toml
[repo]
name = "claims-features"
tags = ["python", "package", "snowflake"]
created = "2026-09-25"
interview = ".ds/interview.md"

[standards.adr-000]
status = "adopted"
version = 1
by = "ckoenigs"
on = "2026-09-25"

[standards.adr-014]
status = "declined"
version = 2
by = "lada"
on = "2026-09-26"
reason = "Pinned to pixi until the SPCS image migration lands (target Q4)."
revisit = "2026-12-01"

[standards.layout]
status = "pending"
version = 3
```

`declined` is a first-class outcome. It requires `by`, `reason`, and
`revisit`. A standard nobody can decline gets silently ignored; one you can
decline by name gets an honest answer, and the org can see who and why.

Manifests roll up nightly to one Snowflake table
(`DS_OPS.STANDARDS.ADOPTION`) so "adr-014: adopted 120, declined 8, pending
72" is one query.

### 4. Interview

`ds new` and `ds migrate` ask; they do not copy. The interview produces the
curated docs set below, and only the sections the answers justify. No empty
headers, no placeholder prose.

```
README.md          local: what this repo is for, who owns it, how to run it
AGENTS.md          mostly pointers: test command, layout, glossary, the
                   instruction to query the graph before reading files
DECISIONS.md       local ADRs, same format as standards/adr, IDs local-001..
.ds/manifest.toml  see above
.ds/interview.md   the questions asked and the answers given, tagged
```

Every emitted line carries provenance: `<!-- local: interview 2026-09-25 -->`,
`<!-- inherited: [[layout@3]] -->`, `<!-- derived: graph 2026-09-25 -->`.
Provenance is what lets the audit tell drift from intent.

`ds migrate` runs the same interview against an existing repo, with the
agent pre-filling answers from the code and the old docs and asking only
where it is unsure. The old docs are kept under `.ds/legacy/` until the
first successful audit, then deleted.

### 5. Reconcile

The one verb. Same code path everywhere it runs.

```
ds reconcile [--check | --apply | --interactive]
```

1. Fetch `standards/index.json` (cached; `--check` works offline).
2. For every standard whose `applies_to` matches this repo's tags and whose
   version is newer than the manifest's: mark `pending`.
3. For every `pending` entry, in `--apply` or `--interactive`:
   - The agent reads the standard and the repo, and produces one of:
     - **adopt**: makes the change (docs, config, or a codemod), runs the
       tests, updates the manifest with `by = "agent:<model>"`.
     - **decline**: writes `reason` and `revisit`; `by` is the human who
       confirmed it, or `agent:<model>` if run unattended, which the audit
       flags for human confirmation within 14 days.
   - `--check` only reports; it never edits.
4. Regenerate derived docs.
5. Validate every pointer resolves.
6. Exit non-zero only on broken pointers or a malformed manifest. Pending
   items are information, not failures.

### Where it runs

| Trigger | Mode | Needs a model | Time |
|---------|------|---------------|------|
| git pre-push hook | `--check`, offline | no | < 1 s |
| CI on merge | `--check` + derived regen | no | seconds |
| `ds reconcile --interactive` | apply with a human | yes | minutes |
| weekly cron per repo | `--apply` unattended | yes | minutes |
| nightly audit (org-wide) | SQL over adoption + graph tables | no | minutes |

The hook is what makes CI optional per push: the deterministic checks run
locally and instantly. CI is authoritative. Only reconcile-with-judgment
needs a model, and it can use the cheapest tier.

### Nightly audit

Queries over the adoption table and the code graph tables already pushed
to Snowflake by CI. Each finding becomes a task in the shared queue.

- Derived contradicts local (docs claim a symbol or command the code lacks).
- Pointer to a superseded standard not yet re-pinned.
- `declined` past its `revisit` date.
- `by = "agent:*"` decline older than 14 days with no human confirmation.
- Repo with no reconcile run in 30 days.
- Glossary drift: new public symbols whose names are not glossary terms or
  their allowed compounds.

## Migration

Not all at once. Order by traffic.

1. Stand up `standards/` with `adr-000`, `glossary`, `layout`, `naming`, and
   the three most contested decisions written as ADRs.
2. Add `ds reconcile`, `ds migrate`, and the hook to `ds`.
3. Migrate the 10 most-touched repos by hand with the interview. Tune the
   questions on those.
4. Migrate the next 30 with the agent pre-filling. Review the interviews.
5. Everything else migrates when next touched, or by a cron that runs
   `ds migrate --apply` and opens an MR. Untouched legacy repos are tagged
   `not-migrated` and excluded from `applies_to` until then.

## Test repo

`standards-bench/`. One codebase, one task list, four runs. Scored by a
script, never by eye.

| Run | Docs | Model |
|-----|------|-------|
| `mash` | raw repo, legacy docs | Opus |
| `system` | interview docs + pointers + manifest | Opus |
| `system-mid` | same | mid-tier (Sonnet or local 30B) |
| `mash-mid` | raw | mid-tier |

Tasks: 20 test-gated changes across the repo, plus 10 cold-start questions
("what is the test command", "which ADR governs dependency management",
"what calls `load_claims`").

Metrics per run:
- tokens per task, by tier
- close rate without human intervention
- tool calls to answer the 10 questions correctly
- **drift score**: apply 15 ADR updates to `standards/`, run reconcile,
  then count doc claims that still match the code (script checks derived
  vs local vs pointer resolution)
- time to first correct answer on cold start

The result that justifies the system is `system-mid` beating `mash` on
close rate and drift at a fraction of the tokens. If it doesn't, the
system is decoration.

## Non-goals

- Replacing Git, CI, or the code graph. This sits beside them.
- A wiki. There is no place to write prose that isn't a Standard, a local
  doc, or derived.
- Forcing adoption. Decline-with-reason is the mechanism; the audit makes
  declines visible, not forbidden.
- Coupling to the local-agent work. This system should make any agent
  cheaper, including Opus in CoCo, before a single local worker exists.

## Consequences

- Standards become the only place org knowledge is written, so they get
  written. Expect the `standards` repo to be the most-reviewed repo.
- Every repo carries a small manifest and a short interview transcript.
  That is the entire per-repo cost.
- Agents read pointers and manifests before code. AGENTS.md shrinks to a
  screen.
- The team sees, for the first time, which decisions are actually in
  force where, and who said no.

## Open questions

- Pointer resolution for people reading on GitLab without `ds`: render on
  commit into a `docs/rendered/` that is gitignored locally but built in
  CI, or accept that GitLab shows `[[ids]]`.
- Whether `revisit` dates should auto-reopen as `pending` or only surface
  in the audit. Leaning audit-only; less churn.
- Local ADR promotion: a `local-00N` decision that three repos make
  independently should become a standard. The adoption table can detect
  the pattern; who writes the ADR is a process question.
